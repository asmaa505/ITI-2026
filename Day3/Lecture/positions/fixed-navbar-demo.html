Notice the red navbar is fixed to the top from the moment the page loads — even before you scroll.

Scroll down... notice the navbar never moves, it's already "stuck" from the start.

What's happening?

This navbar has position: fixed; top: 0; left: 0; width: 100%;. Unlike sticky, a fixed element is removed from the normal document flow immediately — it doesn't wait for a scroll threshold. It's positioned relative to the viewport (the browser window), not its parent container.

The core CSS

.navbar { position: fixed; top: 0; left: 0; width: 100%; z-index: 100; }

The classic "fixed" gotcha

Because the navbar is taken out of the normal flow, the content right below it would normally slide up and hide underneath it. That's why we added padding-top on the wrapper below the navbar — to manually reserve space. sticky doesn't need this trick because it stays part of the normal flow.

fixed vs sticky — quick comparison

fixed: stuck to the viewport immediately, removed from flow, needs manual spacing.
sticky: behaves normally until a scroll threshold (like top: 0), then sticks — but only within its parent container, and stays part of the flow.
